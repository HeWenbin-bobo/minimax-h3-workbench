2026-10-19 在 `feature/pelican-exploration-2026-10-19` 分支上为游乐场加了 `inspect_artifact`、
`read_artifact`、`edit_artifact`、`edit_artifact_batch`（智能体用应用自带 Chromium 真实运行
并修改自己写的 HTML）。以下结论读代码看不出来，都是真机跑出来的：

**1. 报告必须写明"检查的是哪个文件 + 大小 + 修改时间"。**
不加这行时，自检连报两次同一条错后，模型开始怀疑工具"加载了缓存/旧文件"，为此写了两个
探针页、烧掉 4 步。**事后核对磁盘：报错是真的**——它"重写后"的文件里确实还留着那一行
（`M.ident` 19 处、错写 `M.identity` 还留 1 处）。
→ 推论：**工具给了负面结论时，必须附上"我基于哪份输入得出的"。**

**2. "控制台没报错"不等于"画出来了"，必须采样像素。**
Electron 隐藏窗口（`show:false`）能 `capturePage()`；纯色页主色占比 100%、空白画布 97.7%，
"主色 ≥97% 且元素数 > 1"是稳定判据。
**且实测 300ms/1.2s/3s/6s/10s 五个时间点结论完全一致**（99.3% 不变）——1.2 秒采样不产生
假阴性，"重页面画得慢"这个怀疑被真机排除。

**3. 画布要同时报「缓冲区」和「布局」两个尺寸。**
`c.width/height` 是绘制分辨率（几乎总有值），`getBoundingClientRect()` 才是可见面积。
缓冲区 1920×1080 + 布局 0×0 = 画布不占面积，屏幕全白且零报错——真机上模型卡在这上面连改
5 次都没命中。另一种隐蔽形态：**缓冲区停在 HTML 默认的 300×150** 而布局很大 → 脚本在
设置分辨率之前就崩了（真机里模型自己推断出了这句，但花了好几步）。

**4. 控制台的 `lineNumber` 必须带上。**
之前丢掉了，模型拿到报错却不知道在哪一行，把 2100 行的文件分 5 次读完再逐段比对，
光找位置就吃掉 5 步。Chromium 早就把行号给了我们。实测第 10 行的报错能精确标成"第 10 行"。

**5. 失败要给线索，不能只说"找不到"。**
`edit_artifact` 猜错 oldText（缩进差两格）时只回一句"找不到"，模型只能重读+重猜，
单轮重复 4 次。改成返回"最接近的 3 行（行号+原文）"，它照抄即可一轮收敛。

**6. 同一个判定写了两处就会漏一处，成败要用结构化字段。**
`formatProbeReport`（给模型）与 `humanizeToolOutput`（给用户的步骤条）各判一次"是否通过"，
措辞对不上就把空画面说成中性的「自检完成」。另外成败必须用 `ok` 字段传给渲染端——
靠摘要文本猜会渲染出 `✓ 修改文件完成（修改文件失败：…）` 这种自相矛盾的记录。

**7. 加验证环节就必须同步加步数预算；但抬预算治不了浪费。**
加了 `inspect_artifact` 并要求"必须自检到没有报错"，每个修复循环固定多吃 2–3 步，
而预算仍是给"一步生成"定的 10 步 → 连续 7 次真机有 4 次被截断。提到 20 后**仍然打满**，
说明真正的瓶颈是**步骤浪费**（反复重读、凭记忆重猜），要靠第 4、5 条那种
"把定位成本从模型挪到工具"来治。

**8. 预算必须让模型看得见——这条已验证有效。**
同一个表格案例（"做一份国产显卡对比表，做成 Excel"）前后对比：

| | 修复前 | 修复后 |
|---|---|---|
| 步数 | 22 | 28 |
| 调研强度 | 20+ 次搜索、6 个网页 | 同样密集 |
| **产物** | **0 个** | **1 个 xlsx（19KB）** |

差别只在 `prepareStep`：剩余步数进入最后 1/4 时追加一条 user 消息
「只剩约 N 步，请立刻收敛、优先交付」。模型于是真的停止调研去写文件了。

→ 通用结论：**只设上限而不告知，模型会一直以为还来得及**——拦截必须带"提示面"。
载体仍必须是 user 消息；且只在最后 1/4 追加，早期刷屏会稀释注意力。

**9. "画面空白"必须再分一步：渲染循环到底有没有在跑。**
模型连续 5 次改都收到"画面是空的"，但它分不清两种情况，而两者修法完全相反：
① 循环没启动（初始化提前 return / 抛错被吞）→ 查启动路径；
② 页面本来就静止（静态图）→ 根本没坏。

做法：画面是纯色时隔 500ms 再截一帧，逐采样点比颜色桶。
**实测**：rAF 动画页 motion=1.0、只画一次的静态页 motion=0、
真实崩溃的鹈鹕产物 motion=0（与"初始化第 264 行抛错"一致）。
只在纯色时多付这一帧，正常页面不受影响。

→ 推论：**给结论时要给出"能区分两种成因"的那一个观测值**，而不是笼统的"是空的"。

**踩坑记录**：改完源码没 `npm run build` 就跑探针，两次结果都是 `motion=undefined`
——探针加载的是旧 `dist-electron`。CLAUDE.md 记过这条，又犯了一次。

**10. 同名多版本：工具必须永远操作"界面上展示的那一版"。**
界面把 `名字.html` / `名字 (2).html` 折叠成**只显示最新一版**，
而模型手里常还留着旧名字：

    模型：edit_artifact("回落测试.html", "v2", "v3")
    实际：精确命中旧文件 → 改了旧版
    界面：只展示 "回落测试 (2).html" → **毫无变化**

用户对着没变的文件判断"还是坏的"，模型坚信改好了——两边看的是两个文件。
修法：解析统一为「同主名优先取最新版本」，并明确回执"你点名的 X 已过期，实际改的是 Y"。
四个产物工具（inspect/read/edit/editBatch）共用同一个解析函数，别再各写一份。

**11. 编辑后必须推事件，否则界面停留在旧内容。**
`create_file` 会推 `llm:artifact`，但 `edit_artifact` 原本不推 → 卡片大小是旧值、
**已打开的预览不重载**（iframe 走 URL 加载，path 没变就不重新请求）。
修法三处齐全才算完成：主进程推 `updated: true` 事件 → 气泡按 path 就地替换
→ 预览面板加 `revision` 并放进 iframe 的 key 与读盘依赖。

**12. 探针里 `?? "skip"` 这类兜底会让断言永远 PASS。**
`check` 只判真值，而 `?? "skip"` 返回非空字符串 → 预览页再空白也报绿。
另外 `sandbox="allow-scripts"` 的 iframe 是**不透明源**，宿主侧 `contentDocument` 恒为 null；
`h3preview:` 还是**跨进程 iframe（OOPIF）**，`Page.getFrameTree` 看不到它。
正解：`Target.getTargets` 找 url 以 `h3preview:` 开头的 target → `attachToTarget(flatten)`
→ 在该 session 里 `Runtime.evaluate`。拿不到就判失败，不留兜底。

**13. 工具 schema 的"硬校验"会让调用被静默跳过，一次烧光整轮预算。**
AI SDK 在 `parseToolCall` 阶段对 `inputSchema` 做 zod 校验；不通过就抛
`InvalidToolInputError`，**整个 toolCall 记进历史但不执行**——`onToolExecutionStart/End`
都不触发，模型**收不到任何回执**，于是反复重试同一条，20 步预算全烧光；
界面还把原因归成"参数被上游截断"（完全误导）。

2026-10-20 用 mock 探针（`_scratch/probe-schema-*.mjs`）逐个复现并修掉 10 处：
`edits.min(2)`（1 条就整轮报废）、`edits.max(20)`（25 条同理）、
`duration/count` 的 `min/max/int`、`url` 的 `.url()`（不带协议就死）、
`startLine/endLine` 的 `.int().min(1)`（按 0 起算就死）、
`kind` 的 `z.enum`（写 `excel`/`word` 就死，**这是产出物工具，等于什么都拿不到**）、
`status` 的 `z.enum`（写 `done`/`in-progress` 就死，而它几乎每步都调）、
`oldText` 的 `.min(1)`（单处 + 批量）、`keyword` 的 `.min(1)` 与范围不可为 null。

**判据**：只要这个值**代码本来就能自动纠正**（夹紧/截断/归一/补全），就不该做成
schema 硬校验——写进 `describe` 当建议，校验放到 `execute` 里并**回一句可纠正的说明**。
唯一该保留的是"没有它就没法工作"的语义约束（如 `name` 非空）。

**怎么防复发**：`llmService.test.ts` 里有一组契约测试，直接从 `chatAgent` 拿到的工具表里
取 `inputSchema`，用真实 zod 解析验证"别名/越界/空值都能进"。收紧约束会立刻变红。

**探针的两类自欺**（本轮又踩）：① 断言写成 `step === 3`——被跳过时 mock 也会收到第 3 个请求，
两种情况都真，永远绿；必须断言"气泡里有没有『没有真正执行』提示"。② mock 的停止条件
依赖工具结果的**前缀**，而超长正文的回执根本不以那句话开头，导致一直重发到 20 步。

**14. 我们自己的输出格式会被模型照抄回来，然后三处工具各踩一遍。**
`read_artifact` 返回 `    42| code`，模型把这个前缀一起抄进 `oldText`（匹配失败）、
抄进 `newText`（**写进文件**，产物直接坏掉）、抄进 `keyword`（搜不到）。
同一个坑分三次才修完——教训是：**凡是我们给模型看的格式装饰，都要假定它会被原样抄回**，
并在每一个接收侧统一剥掉（`applyExactEdit` / `applyExactEdits` / `findMatchingLines`）。

**15. 编辑写盘要对齐文件原始行尾，三条成功路径都要。**
`applyExactEdit` 有三条成功路径（原样命中 / 行尾归一后命中 / 剥行号后命中）。
只修第一条时，CRLF 文件会经由后两条被**静默改成 LF**（下一次读回时 `` 看不见，
模型照抄的 `oldText` 就匹配不上）。修完三条才一致。
另：产物写盘要**先写 `.tmp` 再 rename**（含 xlsx，显式传 `bookType`），
否则写到一半失败会留下半截文件占住名字。
